# Агент заполнения учёта времени по календарю

Заполняет лист **«Оксана»** таблицы «Учет времени по проектам» по календарю.
Колонки листа: `дата | к-во часов | проект | тип работ | комментарий`.

## Как это устроено

Три шага, намеренно разделённые: распознавание отдельно, правила отдельно, запись отдельно.

```
скриншот календаря  ──(1) Claude, зрение──▶  events/ГГГГ-ММ-ДД.json
                                                    │
                    rules.json ──(2) build_timesheet.py──▶  out/*.xlsx + out/*.tsv
                                                    │
                                        (3) вставка в Google Sheets
```

1. **Распознавание.** Claude смотрит на скриншот и выписывает события дня в JSON:
   `{"start": "09:30", "end": "10:30", "title": "Daily НЛБ"}`. Ничего не решает
   про проекты — только время и название. Там, где по картинке не видно
   длительность, ставит `"uncertain": true` и поясняющий `note`.
2. **Правила.** `build_timesheet.py` применяет `rules.json`: выбрасывает нерабочие
   события, округляет часы, ставит проект и тип работ, схлопывает одинаковые
   пары «проект + тип работ» за день. Здесь нет модели — результат
   воспроизводим и проверяем.
3. **Запись.** Пока вручную: открыть `.tsv` и вставить строки в конец листа.
   Автоматическую дозапись см. ниже.

## Запуск

```bash
python3 timesheet/build_timesheet.py 2026-08-10
```

Печатает сводку по дню, список выброшенных событий и список того, что стоит
перепроверить. Кладёт результат в `out/`:

* `2026-08-10_Оксана.xlsx` — обычный Excel;
* `2026-08-10_Оксана.tsv` — с запятой в дробной части и датой `10.08.26`,
  вставляется в Google Sheets как есть.

## Настройка правил

Весь смысл — в `rules.json`, править его должны вы, а не модель.

* `exclude` — что не идёт в учёт (обед, выходные, чужие события).
* `projects` — подстрока в названии события → проект. **Правила проверяются
  сверху вниз, побеждает первое совпадение**, поэтому специфичные шаблоны
  держите выше общих (`Daily НЛБ` выше, чем `НЛБ`).
* `work_types` — то же для типа работ. Значения взяты из листа «справочники»
  той же таблицы, менять их стоит вместе со справочником.
* `round_hours_to` — шаг округления, сейчас 0.25.
* `merge_same_project_and_type` — схлопывать ли повторы за день.

Если проект или тип работ не распознались, строка всё равно создаётся с
значением по умолчанию, а в конце запуска появляется предупреждение — это
сигнал дописать правило.

## Что дальше

* **Автоматическая дозапись в таблицу.** Быстрее всего — Apps Script,
  привязанный к «Учет времени по проектам», с `doPost`, который принимает
  массив строк и делает `appendRow` в лист «Оксана». Тот же приём уже
  используется в `index.html` для брифа.
* **Календарь вместо скриншота.** Если включить коннектор Google Calendar,
  шаг 1 перестаёт быть распознаванием картинки: события забираются с точными
  временами, а `rules.json` и скрипт не меняются.
